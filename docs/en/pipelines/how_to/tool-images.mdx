# Built-in Tool Images Selection Guide

This page helps you quickly choose the right tool image for your pipeline steps. It offers three ways to find what you need:

1. **Select Image by Scenario** — What do I need to do? Which image should I use?
2. **Find Image by Tool** — I need a specific tool. Which images include it?
3. **Image Details** — Full info for each image: registry, tags, tools, and usage boundaries.

> Note: All image addresses in this document use `registry.alauda.cn:60070` as the example prefix. At runtime, this is automatically replaced with the actual registry address of your environment.

---

## Select Image by Scenario

> Quick start: find your current pipeline step's responsibility and use the recommended image directly.

| Category | Scenario | Recommended Image | Description |
| --- | --- | --- | --- |
| **Source Control** | Code clone, checkout, submodules | [`git-init`](#git-init) | Dedicated git clone image with auth and submodule support |
| | GitLab MR / repo automation | [`glab`](#glab) | GitLab CLI for MR creation, comments, and merges |
| **Build** | Go build and test | [`golang`](#golang) | Full Go toolchain with golangci-lint |
| | Java build, test, and package | [`maven`](#maven) | Maven + JDK 21 |
| | .NET build, test, and publish | [`dotnet`](#dotnet) | .NET SDK LTS image for application compilation |
| | Python scripts and tests | [`python`](#python) | Python + pip |
| **Image & Artifact** | OCI image build and push | [`buildah`](#buildah) | Rootless build, no Docker daemon required |
| | Multi-arch manifest merge (`merge-image` Task), copy, retag, and registry sync | [`crane`](#crane) | Uses `crane index append` to compose and publish manifest lists without a build stage |
| | Helm chart package and publish | [`helm`](#helm) | Includes oras, kubectl, yq |
| **Security & Compliance** | Image/filesystem vulnerability scan | [`trivy`](#trivy) | Pre-loaded vulnerability database |
| | SBOM generation | [`syft`](#syft) | Includes cosign for optional signing |
| | Image signing and verification | [`cosign`](#cosign) | Supports keyless and attestation |
| | Code quality scan | [`sonarqube-scanner`](#sonarqube-scanner) | SonarQube Scanner + JDK 21 |
| | SonarQube pre/post script | [`sonarqube-shell`](#sonarqube-shell) | Minimal bash environment for SonarQube workflows |
| | SonarQube auxiliary CLI | [`sonarqube-cli`](#sonarqube-cli) | Custom sonar CLI for bridging steps |
| **Deploy & Operations** | Kubernetes resource deployment | [`kubectl`](#kubectl) | kubectl + yq |
| | Application CRD management | [`kubectl-app-manager`](#kubectl-app-manager) | kubectl-application plugin + kubectl |
| | GitOps manifest rendering | [`kustomize`](#kustomize) | kustomize + yq + git |
| **General** | Script execution, lightweight automation | [`run-script`](#run-script) | Minimal Alpine with bash/curl/tar |
| | Email notification | [`msmtp`](#msmtp) | Lightweight SMTP client |

> Notes:
>
> - All images run as UID 65532 (non-root user).
> - `latest` usually points to the newest fixed tag but may introduce major version changes. Use fixed tags if stability is a priority.
> - Tool versions are at the `major.minor` level; patch versions are upgraded automatically with image updates.
