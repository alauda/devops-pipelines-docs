# Introduction

Scheduler manages when Tekton PipelineRuns start by connecting them to Kueue queues. It lets administrators control pipeline concurrency and allocate quota across teams. Runs that cannot obtain quota wait before creating TaskRuns or execution Pods, then start automatically when quota becomes available.

## Overview \{#overview}

Scheduler works with the following components:

- **Tekton Operator** installs and configures Scheduler through TektonConfig.
- **Scheduler** assigns queues to PipelineRuns, creates their Kueue Workloads, and releases admitted runs for execution.
- **Kueue** manages queues, quota, and admission order.
- **Tekton Pipelines** executes admitted PipelineRuns.

Scheduler is disabled by default. Cluster administrators enable the component and choose which namespaces use scheduling. Kueue and cert-manager are installed separately; enabling Scheduler does not install these dependencies or create queues.

## Key features \{#key_features}

- **[Concurrency limits](./guides/configure_queues.mdx#set_concurrency_limit)**: Limit the number of admitted PipelineRuns using the `tekton.dev/pipelineruns` quota resource.
- **[Resource quotas](./guides/resource_quotas.mdx)**: Account for CPU, memory, storage, ephemeral storage, and custom capacity alongside concurrency.
- **[Queue isolation and sharing](./guides/configure_queues.mdx#share_quota)**: Give teams separate budgets or let selected namespaces share a ClusterQueue.
- **[Workload priorities](./guides/priorities_and_serial_execution.mdx#prioritize_pipelines)**: Use WorkloadPriorityClasses to order waiting runs when quota becomes available.
- **[Configurable admission](./guides/configure_cel.mdx)**: Use Common Expression Language (CEL) expressions to assign labels, annotations, priorities, and resource requests from PipelineRun metadata.

## Use cases \{#use_cases}

- **Protect a shared build environment**: Keep excess PipelineRuns queued until a concurrency slot is available.
- **Allocate team budgets**: Define dedicated or shared quotas for namespaces that use the same infrastructure.
- **Prioritize release work**: Admit an urgent waiting run ahead of lower-priority work in the same ClusterQueue.
- **Serialize known workloads**: Map selected pipelines or branches to a dedicated queue with a concurrency limit of one while other work uses a separate queue.

## Limitations \{#limitations}

- Scheduling applies to newly created PipelineRuns in namespaces explicitly enrolled by an administrator. Existing runs are not enrolled retroactively.
- Quota represents the requests attached to a PipelineRun. It does not automatically measure the resources used by its Tasks or Pods. Configure Kubernetes resource requests and limits separately.
- Priority controls admission order for waiting work. It does not add capacity or provide a guarantee of interrupting an already admitted run.
- Queue creation and branch-to-queue mappings are administrator-managed. Scheduler does not create queues automatically for new Git branches.
- This documentation covers single-cluster scheduling. MultiKueue workflows are not covered.
